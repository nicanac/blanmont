Les retours visuels

Un bouton permet à chacun de signaler un défaut du site en entourant ce qui ne va pas sur une photo de l'écran. Les responsables lisent, répondent et classent ces retours.

Quand l'outil est allumé, un bouton rouge Donner un avis flotte en bas à gauche de toutes les pages. Le visiteur appuie, entoure le problème, écrit deux phrases et envoie. Le retour arrive dans Retours visuels, où tous les responsables le lisent et le traitent. Le propriétaire du site choisit qui voit le bouton (chapitre 21, page ).

À savoir avant de commencer

Chaque retour est publié sur GitHub, un site public : n'importe qui peut le lire, avec sa photo d'écran. Seul le prénom de l'auteur est publié. Une case à cocher oblige à confirmer qu'aucune donnée personnelle n'apparaît sur la photo.

19.1Envoyer un retour (côté utilisateur)

Cette partie décrit ce que voit un membre ou un responsable qui veut signaler un défaut. Vous pouvez l'essayer vous-même pour vous rendre compte.

  1. Ouvrez la page où se trouve le problème. Restez sur cette page.
  2. Cliquez sur le bouton rouge Donner un avis, en bas à gauche de l'écran.Le bouton se cache pour la photo. Votre navigateur peut demander l'autorisation de partager l'onglet : acceptez, c'est ce qui donne une photo fidèle. Si vous refusez, le site prend une image simplifiée, où les images et les cartes sont vides.
  3. La fenêtre Envoyer un retour s'ouvre avec la photo de la page. Pour attirer l'attention, choisissez un outil et dessinez sur la photo avec la souris ou le doigt.Les annotations sont facultatives. Si une erreur de dessin se produit, cliquez sur Annuler le dernier ou Tout effacer.
  4. Descendez dans la fenêtre et remplissez Titre et Que se passe-t-il ?. Ajoutez, si vous le souhaitez, le Comportement attendu.
  5. Vérifiez le Type et la Priorité.
  6. Relisez la photo : rien de personnel ne doit être visible. Cochez la case orange « Ce retour est publié sur GitHub dans un dépôt public… ».
  7. Cliquez sur Envoyer. Une notification confirme : « Merci ! Retour envoyé (#143). ». Le numéro est celui du retour.

En plus de ce que vous écrivez, le retour contient automatiquement l'adresse de la page, la taille de l'écran, le navigateur utilisé et jusqu'à dix messages d'erreur techniques récents. Ces détails aident à retrouver le défaut. Seul le prénom de l'auteur est publié (« Visiteur » pour une personne non connectée).

Résultat sur le site

Le retour est publié sur GitHub (voir 19.4) et apparaît tout de suite dans la page Retours visuels des responsables, onglet À traiter. Rien n'est modifié sur le site lui-même.

Attention · le nombre de retours est limité

Une même personne (ou une même adresse Internet) peut envoyer 5 retours par période de 10 minutes. Au-delà : « Trop de retours envoyés, réessayez plus tard. ». Une photo trop lourde (plus de 6 Mo) est refusée : « Capture trop volumineuse. ».

19.2Ouvrir la liste des retours et la trier

La liste est accessible de deux façons, avec les mêmes retours et les mêmes boutons.

  • Dans l'administration : cliquez sur Retours visuels dans le menu de gauche, groupe Vue d'ensemble. Un bouton Réglages en haut mène aux paramètres de l'outil (réservé au propriétaire).
  • Depuis le site : cliquez sur Mon Compte, en haut à droite, puis sur Retours. Cette entrée existe pour tous les responsables, même ceux dont le rôle n'ouvre aucune section de l'administration. La page, à l'adresse /retours, est identique. Un simple membre y voit « Accès réservé ».

Lire une carte

Chaque carte résume un retour : la photo de l'écran (ou « Pas de capture »), une pastille de situation (À traiter, Résolu, Écarté), la priorité (rouge pour Bloquant, orange pour Important, bleu pour Suggestion), le type, le titre, un extrait, la page concernée (par exemple /calendrier), l'auteur, la date (« il y a 3 heures », puis la date après 7 jours), le nombre de réponses et le nombre de +1. Un retour Bloquant à traiter porte un trait rouge sur le bord gauche : traitez-le en premier.

Bon à savoir

La liste montre les 300 retours les plus récents. Quand la liste est vide, le message dépend de l'onglet : « Rien à traiter pour le moment. », « Aucun retour résolu. », « Aucun retour écarté. » ou « Aucun retour reçu. ».

19.3Traiter un retour

  1. Dans la liste, cliquez sur l'onglet À traiter.
  2. Cliquez sur une carte pour ouvrir la fiche du retour.
  3. À gauche, regardez la photo. Cliquez sur Ouvrir en taille réelle pour l'agrandir dans un nouvel onglet. Cliquez sur Détails techniques pour voir la page, la taille d'écran, le type de photo (« Onglet (fidèle) » ou « Instantané simplifié »), le navigateur et les erreurs.
  4. À droite, lisez Ce qui ne va pas, le Comportement attendu et les Échanges (les réponses déjà publiées).
  5. Pour passer au retour suivant ou précédent, cliquez sur les flèches en haut à droite (le compteur indique « 1/4 »), ou appuyez sur les touches ← et → de votre clavier.
  6. Si vous le souhaitez, écrivez une réponse dans Votre réponse (facultative) (2 000 caractères au maximum).
  7. Cliquez sur le bouton de votre choix : Marquer résolu, Écarter ou Répondre seulement.

Résultat sur le site

Rien ne change sur le site lui-même. Le retour est classé dans l'onglet voulu, et sa fiche publique sur GitHub est refermée ou rouverte. Votre réponse est visible par tous ceux qui lisent la fiche sur GitHub, avec votre prénom et votre rôle.

Attention · vos réponses sont publiques

Écrivez comme si votre message était affiché sur une place publique : pas de numéro de téléphone, d'adresse ni de remarque sur une personne. Une fois publiée, une réponse ne peut pas être retirée depuis le site.

Donner un +1

Le +1 sert à dire « moi aussi » : il fait monter le retour dans le tri Plus votés.

  1. Ouvrez la fiche d'un retour.
  2. Cliquez sur +1, en bas à droite. Le nombre à côté augmente de un et le bouton devient rouge.
  3. Pour retirer votre vote, cliquez de nouveau sur le même bouton.

Chaque personne ne peut voter qu'une fois par retour. Les votes sont conservés par le site, et non sur GitHub.

19.4Ce qui se passe sur GitHub

GitHub est un site public où les développeurs suivent leur travail. Le site du club s'en sert comme boîte aux lettres des retours : chaque retour y devient une fiche, et c'est de là que la liste est relue.

ActionCe qui est écrit sur GitHub
Un utilisateur envoie un retourUne fiche est créée, avec le titre précédé d'un numéro de retour (par exemple « [REV-k3m9x] »). Sa photo est enregistrée dans le dépôt du club. La fiche est publique.
Marquer résoluLa fiche est fermée comme « terminée ». Un commentaire est ajouté : « Marqué comme résolu. », signé de votre prénom et rôle, avec la mention « via l'application ».
ÉcarterLa fiche est fermée comme « ne sera pas traitée ». Commentaire : « Écarté (ne sera pas traité). ».
RouvrirLa fiche est rouverte. Commentaire : « Rouvert. ».
Répondre seulementVotre texte est ajouté comme commentaire.
+1Rien : le vote reste dans la base du club.
Si une photo montre des données personnelles

Si un retour publié montre un nom, un visage ou un courriel, il faut le faire retirer de GitHub sans attendre : le site ne permet pas de supprimer une fiche. Prévenez le propriétaire du site, qui a la main sur le compte GitHub du club.
